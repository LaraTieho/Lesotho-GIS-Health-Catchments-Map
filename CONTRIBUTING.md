# Contributing to Lesotho Health Facilities Catchments Map

Thank you for contributing to this project. This repository supports a national geospatial planning system for PHC and EPI in Lesotho, so contributions must be accurate, documented, and reviewable.

## Before You Start

Please read:

- `README.md`
- `CODE OF CONDUCT.md`
- any dataset-specific metadata files
- the changelog, if available

## How to Contribute

### 1. Open an Issue First

Before making major changes, open an issue describing:

- the problem or improvement
- the dataset or layer affected
- the expected outcome
- any evidence or source documents available

### 2. Use a Branch

Create a branch with a clear name, for example:

- `fix/village-names-maseru`
- `update/roads-layer-validation`
- `docs/metadata-cleanup`

### 3. Keep Changes Focused

Each pull request should address one main topic only. Avoid combining unrelated data edits, layout changes, and documentation changes in the same request.

### 4. Protect Authoritative Data

Do not overwrite validated or published layers without review. Use the project’s editing and approval workflow for:

- villages
- roads
- schools
- health facilities
- settlement extents
- catchment boundaries

### 5. Validate Your Changes

Before submitting, check that:

- geometry is valid
- fields are complete
- names and codes are consistent
- CRS is correct
- symbology and labels still render properly
- metadata is updated where necessary

### 6. Document What Changed

Every contribution should explain:

- what changed
- why it changed
- which dataset was affected
- which source was used
- whether the change is draft, reviewed, or approved

## Suggested Pull Request Checklist

- [ ] Issue opened and linked
- [ ] Change is limited and relevant
- [ ] Data validated
- [ ] Metadata updated
- [ ] No broken links or paths
- [ ] No unauthorized edits to authoritative layers
- [ ] Screenshots or map previews attached if relevant

## Data and Documentation Standards

Please maintain:

- clear file names
- consistent layer naming
- version numbers
- update dates
- source lineage
- contact information for stewardship

## Review Process

Maintainers may request:

- clarification
- correction
- additional validation
- improved documentation
- separation of draft and published materials

## Questions

If you are unsure how to proceed, open an issue and describe the intended change before editing files.
